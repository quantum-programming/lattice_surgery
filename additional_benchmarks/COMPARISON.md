# Reviewer 1 comparison

This directory contains one deliberately small comparison between the planar
compiler in this work and TopoLS. It is intended to expose their different
representations and resource assumptions, not to rank unlike native metrics.

## Inputs and configurations

The checked-in OpenQASM inputs are generated by MQT QECC commit
`f3c26db10727174af2d2d7c02d1fbee70162a1c0`. Both contain six qubits and 24
CNOTs (seed 45): `mqt_max_parallel` maximizes layer parallelism, while
`mqt_min_parallel` uses `layer_size=2` and deliberate qubit reuse.

Our configuration uses the existing one-layer outer allocator (SA seed 1,
1,000,000 iterations), Double look-ahead scheduling, `CareKinkParity`, and the
native schedule validator. TopoLS uses block size 10, ZX and direction
optimization, the Python reference engine, initial seed 0, and its five-seed
search. Inputs and external implementations are unchanged.

Run from this directory under WSL/Linux:

```bash
work/venv-wsl/bin/python scripts/run_comparison.py
work/venv-wsl/bin/python -m unittest discover -s tests -v
```

## Results

| Circuit | This work: depth / allocated sites / occupied volume | TopoLS: depth / space / bounding-box volume | ZX vertices |
|---|---:|---:|---:|
| max parallel | 11 / 81 / 178 | 22 / 45 / 990 | 60 → 47 |
| min parallel | 11 / 81 / 166 | 16 / 45 / 720 | 60 → 48 |

The units and accounting boundaries differ. Our depth is measured in code
beats. Its occupied volume counts persistent data storage and routed ancillary
sites, whereas allocated volume is the full 9×9 grid times depth (891 for both
circuits). TopoLS reports pipe-diagram coordinates and their geometric bounding
box. These numbers must therefore not be divided into a cross-tool improvement
factor.

Our regular layout has nine candidate data slots in 81 sites (11.1% at this
small size) and six active data patches (7.4%). Its data-slot density approaches
25% asymptotically; the 16 boundary MSF sites are allocated separately. TopoLS
instead simplifies and slices a ZX graph before placing merge–split structure
in 3D, so no static storage-density parameter is defined for it. The reductions
in ZX vertices above show the pre-placement merging, but are not themselves
volume reductions.

`results/comparison.json` records exact inputs, revisions, settings, metrics,
and accounting fields. `figures/structure_comparison.png` renders the
min-parallel outputs with a shared coordinate convention and drawing style.
